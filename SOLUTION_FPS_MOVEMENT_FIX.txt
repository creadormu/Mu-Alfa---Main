ROOT CAUSE:
════════════════════════════════════════════════════════════════════════════════
In HackCheck.cpp, line 137:
    Cmp Dword Ptr Ss:[Ebp-0x68],0x28    // Compares with 40ms (HARDCODED!)

Line 188:
    Mov Dword Ptr Ss:[Ebp-0x68],0x28    // Sets to 40ms (HARDCODED!)

This means the frame limiter ALWAYS uses 40ms regardless of LimitFPS value!

SOLUTION 1: PROPER FRAME LIMITING
════════════════════════════════════════════════════════════════════════════════

Option A: Disable the hardcoded limiter and use VSync only
────────────────────────────────────────────────────────────────────────────────
Add to Main.cpp after FPS dialog:

    // Disable hardcoded 40ms frame limiter
    SetByte(0x004DA3DC, 0x90);  // NOP the comparison
    SetByte(0x004DA3DD, 0x90);
    SetByte(0x004DA3DE, 0x90);
    
    // Let VSync control frame rate
    // CEffect.dll will handle rendering

This allows the game to run at monitor refresh rate with VSync.

Option B: Patch the hardcoded values dynamically
────────────────────────────────────────────────────────────────────────────────
Add to Main.cpp after FPS dialog:

    DWORD targetFrameTime = gProtect.m_MainInfo.LimitFPS;
    
    // Patch the comparison value at 0x004DA3DE
    SetByte(0x004DA3DE, (BYTE)targetFrameTime);
    
    // Patch the assignment value at 0x004DA48D  
    SetByte(0x004DA48D, (BYTE)targetFrameTime);

This makes the frame limiter respect your LimitFPS value.
